# MCL Building Branch — Stakeholder Presentation Brief

## The Problem

Building-related complaints and field violations involve:
- Multiple officers
- Physical visits
- Evidence
- Notices
- Follow-up
- Delays
- Senior-level decisions

When records are fragmented or manually tracked, it becomes difficult to know:
- What is pending
- Who is responsible
- How long a matter has been delayed
- What action has already been taken
- Which officers/cases require attention

## The Proposed System

MCL Building Branch creates one internal digital workflow for:
- Receiving complaints
- Assigning responsible officers
- Recording BI field visits
- Storing evidence
- Tracking enforcement cases
- Recording notices
- Monitoring status history
- Identifying delayed cases
- Providing analytics to senior officers

## Why Complaints and Cases Are Different

A complaint is information received about a possible issue.

A case is an official building/violation matter being tracked for action.

The system keeps these separate but allows a complaint to lead into a case.

## Evidence and Accountability

Each BI field update requires:
- Evidence image
- Written report

This creates a clear record of what was observed and when.

## Delay Monitoring

A case can remain pending for too long.

The system will:
- Measure time spent in stages
- Automatically flag delayed cases
- Calculate a priority score
- Rank flagged cases
- Make them visible to senior officers

Flags do not change the official case status.

## Analytics

The dashboard can show:
- Total cases
- Pending cases
- Closed cases
- BI activity
- ATP performance context
- Delayed/flagged cases
- Severity trends
- Daily/weekly/monthly performance

## Notifications

The system is planned as a PWA primarily to support notifications such as:
- New assignment
- BI update
- Review required
- Notice expiry
- Serious enforcement stage
- Delayed case escalation

## Prototype Demonstration

The prototype demonstrates:
1. Complaint registration
2. Assignment
3. Field inspection
4. Evidence and report
5. ATP review
6. Case creation
7. Notice/enforcement progression
8. Delay flagging
9. Analytics

The goal is to demonstrate the complete concept clearly while continuing development toward the full production workflow.
